# The Bureau of Questionable Knowledge

A shared-screen British party game for one to four players, built with React, TypeScript and Vite. The fictional, independent Bureau has seventeen playable departments; a full assessment draws eight distinct departments plus mini-games, secret directives and a final case. It is not affiliated with or endorsed by any government, public authority or the Royal Household.

## Run locally

Requires Node.js 22.12–24.x and pnpm 11.19.0. These versions are pinned in `package.json`; use Corepack or install the matching pnpm release before a clean install.

```powershell
pnpm install
pnpm dev
```

Open `http://localhost:3000`. The opening screen now keeps advanced configuration behind **Customise assessment**. **First Assessment** registers one to four candidates and introduces four approachable departments with a one-time three-step control demonstration, without a timer, private directives, assets, committee votes or an extra final case. **Recommended Multiplayer** starts a balanced Quick match for two to four players using mixed questions, guided demonstrations, no timer and Light Office Politics. Quick, Standard and Full Bureau games randomly draw four, six and eight distinct rounds respectively from all seventeen departments. Custom Assessment lets the host select and reorder four to eight departments. Host options include Relaxed, Standard and Rapid continuous-scoring pace profiles, independently of the optional 30, 45 and 60-second turn timer, plus Office Politics controls.

On Windows, `Run The Bureau.ps1` starts the local server and opens the game. New hosts should begin with First Assessment; returning groups can use Recommended Multiplayer without configuring the advanced options. Completed control demonstrations are retained in browser and Windows recovery data. See `HOST-QUICK-REFERENCE.md` for the one-page hosting guide.

## Release checks

```powershell
pnpm check
pnpm e2e
pnpm development:report
pnpm balance:beta
pnpm security:audit
pnpm playtest:verify playtest-results
pnpm rc:verify
pnpm rc:go
pnpm commercial:check
pnpm release:windows
```

The normal check regenerates release records, audits editorial structure, performs strict TypeScript checking, deterministic rules, desktop-shell tests, the production web build and the Playwright browser/Electron regressions. `security:audit` checks both the shipped and development dependency trees against the current registry advisories; it is mandatory in release-candidate and commercial distribution commands. `playtest:verify` certifies consented, pseudonymous beta evidence against the attested solo First Assessment, two-candidate Quick/Light and four-candidate Standard/Standard matrix, proves every scheduled department produced an event, checks measured completion time and candidate ratings, and writes `PLAYTEST-CERTIFICATION.json` plus `PLAYTEST-FINDINGS.md`. It does not infer or fabricate independence: the in-game recorder requires a separate eligibility attestation before the session can be armed. `rc:verify` repeats the complete automated suite, rebuilds and verifies the installer, and writes an evidence-based `RELEASE-CANDIDATE-STATUS.json`; a `NO_GO` result is expected while human and commercial evidence is incomplete. `rc:go` fails unless every legal, content, accessibility, performance, installation, full-match and known-defect gate passes. `release:windows` runs the automated gate, produces the portable executable, inspects the packaged ASAR and Windows metadata, rejects development files or runtime dependencies, and writes `release/SHA256SUMS.txt`. `commercial:check` is deliberately stricter: it blocks a commercial package while any asset group is conditional or the legal publisher, professional trade mark decision or release agreement remains incomplete. See `E2E-REGRESSION.md` for the automated match, recovery, accessibility and screenshot matrix.

Stage-six editorial records are generated by `pnpm release:records`. `pnpm editorial:audit` checks that all 425 challenges have sources, accepted answers, rationales, difficulty reviews, aliases, content fingerprints and any required time-sensitive deadline. The source register now contains 599 authority links and one complete bibliographic fallback. `pnpm editorial:certify` is intentionally stricter and remains blocked until a person other than the question author has approved every challenge against its current fingerprint. Independent editors work through `EDITORIAL-REVIEW-QUEUE.csv` in batches, dry-run a completed copy with `pnpm editorial:import -- <completed-review.csv>`, then add `--write` only after validation passes. Approval requires all six independence, source, wording, answer, difficulty and play-test attestations. See `EDITORIAL-POLICY.md`; automated tooling never invents human approval.

Development builds expose a directly selectable visual-state gallery at `http://localhost:3000/dev/gallery`. It covers all seventeen departments, six apparatus states, one-, two- and four-candidate layouts, and deliberately long questions. Use `VISUAL-PLAYTEST-PROTOCOL.md` for the viewport, keyboard, reduced-motion and human-session certification procedure.

The live rules laboratory at `http://localhost:3000/dev/round-lab` mounts the real round components. It can select any department and challenge, switch between one, two and four candidates, change the starting candidate, enable the optional timer and restart a fixture without playing the preceding assessment. The nine promoted departments are **Misfiled Records**, **Redacted Records**, **Common Dossier**, **Missing Minutes**, **Public Enquiry**, **Chain of Command**, **The Complaints Desk**, **The Seating Committee** and **The Dispatch Box**. Each has 25 files and is eligible for normal random or custom assessments.

The post-assessment replay laboratory at `http://localhost:3000/dev/post-assessment` opens a populated ceremony with two candidates, score progression, department records and a host-adjudicated answer. It also verifies that `Same Candidates, New Random Assessment` retains the candidates and match settings while drawing a different itinerary.

For a reproducible challenge/event sequence, add a numeric seed to the URL, for example `http://localhost:3000/?seed=42`.

## Match architecture

Match orchestration is reducer-owned. `MatchState` contains the candidates, active challenge, progression, score history, Bureau Review, mini-games, armed assets, Office Politics and final-case position; `src/game/matchOrchestration.ts` applies scoring and transitions as deterministic functions. React retains only presentation state such as open overlays and dispatch animation. Active assessments are saved as session format v4, with safe migration from v1–v3.

## Host notes

- The game uses one shared screen. Secret directives, sealed estimates, witness briefs, jury ballots and Committee votes use a full-screen Confidential Handover curtain. Pass the device to the named candidate; they confirm their identity before private controls appear.
- Progress is stored locally and an unfinished assessment can be resumed after refresh.
- The Atlas Room uses a bundled, label-free UK map derived from OpenStreetMap data. It does not require network access or download tiles during play.
- Image Reveal photographs and the Bureau's typefaces are packaged locally; failed media is replaced with an explicit clue-only state. Normal play requires no internet connection.
- Use the question-mark control during a match for rules or to end and discard the active assessment.
- The same host dossier can pause the timer, restart an attempt or skip a blocked challenge for zero points; destructive actions require confirmation.
- The host dossier records structured play-test evidence only after explicit participant consent. It stores timings and observer-marked incidents locally; nothing is transmitted automatically.
- The same dossier can arm a pseudonymous structured blind session and collect an enjoyment/clarity debrief at the podium. Its beta JSON/CSV exports exclude candidate names, recovery data and free-text notes. See `CLOSED-BETA-GUIDE.md` and `BLIND-PLAYTEST-PROTOCOL.md`.
- Free-text rounds pause for a host ruling when an answer does not exactly match a filed name or alias. The host may accept, edit and accept, or reject it.
- The final ceremony includes individual performance dossiers and can restart with the same candidates while avoiding recently used challenges.
- Random assessments can mark departments as favourites or exclusions. Preferences persist locally, favourites receive additional scheduling weight, exclusions remain bounded so a full eight-department assessment is always possible, and the previous two completed itineraries are avoided where the available pool permits.
- Office Politics opens one Committee Window per round. Correct predictions earn Influence; motions can raise the target standard, counter-sign a successful score or request a Second Reading without removing turns or taking earned points.
- Influence is capped at three. A trailing candidate receives one free motion, while any player with Influence may contribute one point to reveal a shared final-case clue.

## Supported browsers

Current Chrome, Edge, Firefox and Safari releases with JavaScript, local storage and Web Audio enabled. A keyboard-visible focus treatment and reduced-motion mode are included.

## Input and accessibility

- Every essential action is available through a native control or a documented keyboard surface. Touch targets are at least 44 pixels and visible focus is retained throughout play.
- In the Atlas Room, focus the map and use the arrow keys to plot, hold Shift for larger steps, press Space to place the first pin and Enter to lock the coordinates.
- Rank It and The Seating Committee provide visible move controls as well as drag interaction, with position changes announced to assistive technology.
- Dossiers and other modal windows trap focus while open, support Escape where dismissal is safe and restore focus to the previous control or current round afterwards. Confidential Handover curtains deliberately cannot be dismissed with Escape and keep focus on the named-recipient confirmation.
- Score, candidate, department, life and timer changes use concise status announcements. Timer announcements are limited to pause, resume and the 10-, 5- and 0-second thresholds.
- Active interactions are contained within the desktop viewport. Tablet, mobile and layouts enlarged to 200% use normal document scrolling rather than clipping controls.
- Reduced-motion mode removes travel and scale effects without adding a delay to results.

## Content policy

Challenge answers live in `src/data/questions.ts`, `src/data/supplementalQuestions.ts`, `src/data/expansionQuestions.ts`, `src/data/prototypeQuestions.ts` and `src/data/promotedQuestionExpansion.ts`. All 17 departments have 25 challenges each (425 total). New material should include a stable source description, aliases that do not create false positives, and a peer check of every accepted answer before release.

Free-text answers in Top 10, Put Up or Shut Up and The List use canonical and alias matching with punctuation, article and plural normalisation. Unmatched answers pause for host Accept, Reject or Edit decisions before penalties apply. The latest ruling can be undone, and automatic, host-made and reversed decisions are retained in the post-assessment dossier with their matching reason.

All 17 departments use the same Bureau Finding result dossier. Each apparatus names its current control in a text-backed legend, while processing, accepted, rejected and result states combine an explicit status ribbon with lamps and mechanical movement. Routine processing and dispatch timing is defined centrally in `src/game/presentation.ts`: ordinary result sequences remain below 700 ms, major reveals remain below two seconds, and reduced-motion timing is capped. Candidate, department, Bureau Review, annex and Final Case hand-offs use a concise automatic dispatch notice rather than another confirmation click.

Department sound cues are generated locally from eight original mechanical motifs—ratchet, shutter, gavel, pressure, capsule, rail, iris and gauge—with filtered transients and restrained resonances. They use no third-party samples, remain optional, and never carry required state without visible text. Master, effects and mute preferences persist locally; the technical review is recorded in `AUDIO-QUALITY-REVIEW.json`.

Image Reveal media is sourced from Wikimedia Commons. The local files cover the Rosetta Stone, Angel of the North, Glenfinnan Viaduct, Tower Bridge, Stonehenge, Edinburgh Castle, Elizabeth Tower, Giant's Causeway, Forth Bridge, the Kelpies, Sutton Hoo helmet, Supermarine Spitfire, Caernarfon Castle, Hadrian's Wall and the Cerne Abbas Giant. Core author, licence, source, modification and file-hash records are generated into `public/assets/reconnaissance/CORE-LICENCES.json` and `ASSET-RIGHTS.json`.

The expansion photographs cover the White Cliffs of Dover, Blackpool Tower, Royal Pavilion, Falkirk Wheel, Clifton Suspension Bridge, Stirling Castle, Durham Cathedral, Royal Liver Building, Menai Suspension Bridge and Glastonbury Tor. Their author, source and Creative Commons licence records are stored in `public/assets/reconnaissance/EXPANSION-LICENCES.json`.

Additional Bureau machinery artwork was generated specifically for this project. The current responsive v4 apparatus pack supplies purpose-built Map, Bidding, Top 10, The List, Closest Wins, Rank It, Image Reveal and Stop the Score machinery. ## Score economy certification

`pnpm run development:report` runs seeded match, department, pacing and strategy laboratories. It reports continuous score distributions; checks one-, two- and four-candidate seat spread; compares cautious, balanced and aggressive risk; audits Office Politics power; verifies the rising schedule-momentum arc; and certifies the duration ranges shown at setup. `pnpm balance:beta` separately analyses real schema-v5 play-test exports, excludes scores not attached to an eligible complete session and remains evidence-pending until six independent groups and eight attempts per department are present. The release gate fails on a dominant strategy or seat, a repetitive schedule, an unreliable duration range or an uncontestable politics threshold. These are simulation guardrails, not fixed in-game score categories: live awards continue to be calculated from actual accuracy, distance, elapsed time, risk, evidence used or valid answers supplied. The full contract is in `PACING-AND-BALANCE.md` and `BALANCE-PLAYTEST-PROTOCOL.md`.

## Windows desktop package

The thin Electron wrapper is in `electron/`. It serves the packaged build from a stable private `bureau://app` origin, so there is no localhost port conflict. Existing browser save keys are preserved in Electron's per-user profile and can be moved with the **Export recovery file** and **Import web save** controls on the opening screen. Placing `bureau-storage-export.json` beside the portable executable also imports it automatically on first launch.

The desktop app supports F11 fullscreen, remembers its window state, confirms before quitting an active assessment and offers recovery after a renderer crash. Build and verify the portable Windows release with `pnpm release:windows` (`pnpm desktop:dist` is an alias). The Electron toolchain is a development-only download of approximately 150–250 MB and is not included in the final source checkout.

The release executable is written to `release/Bureau-of-Questionable-Knowledge-1.0.0-rc.1-portable-x64.exe`. It needs no Node.js installation, terminal or localhost server. Recovery data remains local to the Windows user profile unless the host explicitly exports it. A renamed Windows build imports a valid recovery record from the former `The Bureau` per-user folder on first use.

Public commercial packaging uses `pnpm commercial:dist`. It requires the rights gate to pass and signing credentials to be supplied out of band as `WIN_CSC_LINK` and `WIN_CSC_KEY_PASSWORD` (or their `CSC_` fallbacks); values must never be committed. The command also rejects an executable whose Authenticode status is not valid.
